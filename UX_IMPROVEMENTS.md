# Предложения по улучшению UX бота

Дата анализа: 2026-04-16

---

## Критичное (влияет на каждого пользователя)

### 1. В расписании не показывается предмет — только время
**Файл:** `handlers.py`, команды `/schedule` и `/today`  
**Проблема:** Пользователь видит `⏰ 10:00`, но не понимает, что за занятие.  
**Решение:** Добавить в таблицу расписания поле `subject_name` и отображать его рядом со временем.

### 2. Нет постоянной Reply-клавиатуры
**Файл:** `handlers.py`, функция `start_command`  
**Проблема:** Пользователь должен знать команды наизусть или постоянно открывать `/help`.  
**Решение:** При `/start` показывать постоянную кнопочную панель:
- 📅 Расписание на неделю
- 📅 Сегодня
- 🤖 Спросить репетитора
- ❓ Помощь

### 3. Двойная регистрация обработчиков
**Файл:** `bot.py`, строки ~96–103  
**Проблема:** `register_handlers` вызывается дважды — сначала для первого `application`, потом для пересозданного с колбэками. Потенциальные дубли обработчиков.  
**Решение:** Вынести создание `application` с `post_init` / `post_shutdown` в отдельный шаг, вызывать `register_handlers` один раз.

## Важное (частые сценарии)

### 4. Индикатор "печатает" гаснет через 5 секунд
**Файл:** `handlers.py`, функция `handle_message`  
**Проблема:** `send_action("typing")` исчезает раньше, чем AI даёт ответ (особенно при Ollama на слабом железе).  
**Решение:** Один из двух вариантов:
- Повторять `send_action("typing")` каждые 4 секунды в фоновой задаче до получения ответа.
- Отправлять сообщение-заглушку "🤔 Думаю над ответом..." и редактировать его готовым ответом через `edit_message_text`.

### 5. Технические сообщения об ошибках видит ученик
**Файл:** `modules/ai_tutor.py`, метод `process_question`  
**Проблема:** Сообщения вида "Убедитесь, что Ollama запущен: `ollama serve`" показываются пользователям, которые являются детьми/учениками.  
**Решение:** Два уровня ошибок:
- Пользователю: "😔 Репетитор временно недоступен. Попробуй позже или обратись к администратору: @support"
- В лог: полный технический текст с деталями провайдера.

### 6. Онбординг для пользователей без назначенной группы
**Файл:** `handlers.py`, все команды, проверяющие `group_name`  
**Проблема:** При отсутствии группы — тупик: "Обратись к администратору." Никаких следующих шагов.  
**Решение:** Показывать список доступных курсов и inline-кнопку "📞 Написать администратору" со ссылкой на `support_contact` из конфига.

## Улучшения качества

### 7. Быстрые вопросы — двухшаговый неудобный флоу
**Файл:** `handlers.py`, функция `handle_quick_question_callback`  
**Проблема:** Нажал "📝 Объясни тему" → бот просит ввести тему текстом → пользователь теряется, не понимает, что от него ждут.  
**Решение:** Показывать inline-кнопки с конкретными темами группы пользователя (берутся из `TUTOR_SPECIALIZATION` / `organization.yaml`), чтобы выбрать в один клик.

### 8. Кнопки оценки ответа показываются слишком часто
**Файл:** `handlers.py`, функция `handle_message`  
**Проблема:** "✅ Понял / ❌ Не понял" после каждого сообщения — быстро начинает раздражать.  
**Решение:** Показывать кнопки оценки не чаще чем раз в 5 сообщений или только при первых N диалогах с новым пользователем.

### 9. Контекст AI-диалога не сбрасывается при повторном /start
**Файл:** `handlers.py`, функция `start_command`; `database.py`  
**Проблема:** Пользователь нажимает `/start` снова (ожидает "чистый лист"), но история диалога с AI продолжается с прошлых сообщений.  
**Решение:** При `/start` очищать историю диалога пользователя в таблице `conversation_history` или помечать её как неактивную.
