# Исправление ошибки базы данных

## Проблема

Ошибка: `sqlite3.OperationalError: no such column: class_level`

Это происходит, если в базе данных уже есть старая структура таблицы `schedule`.

## Решение

Код теперь автоматически проверяет структуру таблицы и пересоздает её, если нужно.

### Вариант 1: Автоматическое исправление (РЕКОМЕНДУЕТСЯ)

Просто запустите `load_data.py` снова - код автоматически обнаружит старую структуру и пересоздаст таблицу:

```bash
python load_data.py
```

**Внимание:** Все старые данные в таблице `schedule` будут удалены!

### Вариант 2: Удалить базу данных вручную

Если хотите начать с чистого листа:

1. Удалите файл базы данных:
   - Windows: `data\bot.db`
   - Linux/Mac: `data/bot.db`

2. Запустите `load_data.py`:
   ```bash
   python load_data.py
   ```

### Вариант 3: Через SQLite консоль

Если работаете напрямую с SQLite:

```sql
-- Открыть базу данных
.open data/bot.db

-- Удалить старую таблицу
DROP TABLE IF EXISTS schedule;
DROP TABLE IF EXISTS user_subjects;

-- Удалить старые индексы
DROP INDEX IF EXISTS idx_schedule_date;
DROP INDEX IF EXISTS idx_schedule_subject_date;
DROP INDEX IF EXISTS idx_schedule_user_date;
```

Затем запустите `load_data.py` - таблицы создадутся автоматически.

## Что было исправлено

1. ✅ Добавлена автоматическая проверка структуры таблицы `schedule`
2. ✅ Автоматическое пересоздание таблицы при обнаружении старой структуры
3. ✅ Добавлена проверка и добавление поля `full_name` в таблицу `users`

## После исправления

После того как таблицы пересозданы, загрузите данные:

```bash
python load_data.py
```

Все должно работать!
