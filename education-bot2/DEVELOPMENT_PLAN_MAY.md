## 1. Текущее состояние проекта

### Реализовано

- Telegram-бот с командами: `/start`, `/help`, `/status`, `/schedule`, `/today`
- AI-репетитор (Ollama, Groq, Gemini, OpenAI), специализация по группам
- Расписание по группам, уведомления о занятиях (в т.ч. в реальном времени)
- Админ-приложение (PyQt5): таблицы «Учащиеся» и «Расписание», выпадающие списки групп/дней
- Сохранение данных в SQLite, загрузка из приложения в БД
- Загрузка из CSV/Excel через отдельные скрипты (`admin_loader.py`, `admin_loader_excel.py`)
- Удалённое подключение к Ollama (VPN, Cloudflare Tunnel)

### Не реализовано (в scope плана)

- Загрузка данных из Excel напрямую из оконного приложения (кнопка «Загрузить из Excel»)
- Парсинг мероприятий с сайтов и рассылка по группам
- Мультитенантность и «под ключ» развертывание для организаций
- Часть дополнительного функционала из раздела 5

## 2. Фаза 1: Интеграция с Excel

**Цель:** Администратор может загрузить данные из Excel в таблицы приложения одной кнопкой, без ручного копирования.

### 2.1. Требования

- В админ-приложении (table.py) добавить кнопку **«Загрузить из Excel»** (или две: «Учащиеся из Excel» и «Расписание из Excel»).
- Выбор файла через диалог (один или два файла: учащиеся и расписание).
- Парсинг выбранных листов/колонок и заполнение таблиц в окне (не только загрузка в БД).
- Поддержка форматов: `.xlsx`, при необходимости `.xls`.
- Обработка ошибок: неверные колонки, пустые ячейки, дубликаты — сообщения пользователю без падения приложения.

### 2.2. Технические задачи

| № | Задача | Описание | Приоритет |
|---|--------|----------|-----------|
| 1.1 | Диалог выбора файла | QFileDialog, фильтр `*.xlsx`, опция «Учащиеся» / «Расписание» / «Оба». | Высокий |
| 1.2 | Парсинг Excel | Использовать существующую логику из `admin_loader_excel.py` (pandas/openpyxl). Вынести парсинг в отдельный модуль `excel_parser.py` с функциями `parse_users_excel(path) -> list`, `parse_schedule_excel(path) -> list`. | Высокий |
| 1.3 | Маппинг колонок | Поддержка разных названий колонок (User ID / user_id, Группа / group_name, День недели / day_of_week и т.д.). Либо автоопределение по первой строке, либо настраиваемый маппинг (словарь в коде или простой конфиг). | Высокий |
| 1.4 | Заполнение таблиц в UI | После парсинга: очистить/добавить строки в `users_table` и `schedule_table`, подставить значения, в т.ч. в комбобоксы (Группа, День недели). Учесть `_ensure_schedule_row_widgets` и т.п. | Высокий |
| 1.5 | Валидация и отчёт | Проверка: обязательные поля, формат времени, список групп/дней. Вывод отчёта (QMessageBox или отдельное окно): «Загружено N учащихся, M записей расписания», предупреждения (например, неизвестная группа). | Средний |
| 1.6 | Шаблоны Excel | Кнопка «Скачать шаблон» или ссылка на шаблон в папке `data/` (users_template.xlsx, schedule_template.xlsx) с подписанными колонками. | Низкий |

### 2.3. Приёмы критерий готовности

- Администратор выбирает Excel с учащимися и/или расписанием и видит данные в таблицах приложения.
- После загрузки можно нажать «Загрузить в базу данных» — данные уходят в ту же БД, что и при ручном вводе.
- Документация: краткая инструкция в README или ADMIN_GUIDE по формату Excel и кнопке «Загрузить из Excel».

## 3. Фаза 2: Парсинг мероприятий и уведомления

**Цель:** Собирать с внешних сайтов информацию о мероприятиях (вебинары, митапы, олимпиады и т.д.), привязывать к темам групп и отправлять уведомления учащимся соответствующих групп.

### 3.1. Требования

- Настраиваемый список источников (URL + правила парсинга или RSS).
- Привязка «группа ↔ темы/ключевые слова» (например, «Пайтон для начинающих» → python, программирование, вебинары).
- Периодический парсинг (по расписанию, например раз в день).
- Фильтрация по дате (только предстоящие мероприятия).
- Рассылка сообщений в Telegram только тем учащимся, чья группа совпадает с темой мероприятия.
- Избежание дубликатов (одно и то же мероприятие не присылать дважды).

### 3.2. Технические задачи

| № | Задача | Описание | Приоритет |
|---|--------|----------|-----------|
| 2.1 | Модель данных | Таблица `events` (id, source, title, description, url, date_start, date_end, topics_json, created_at). Таблица `group_topics` (group_name, keywords_json) для маппинга группа → ключевые слова. | Высокий |
| 2.2 | Конфиг источников | Файл конфигурации (YAML/JSON) или админ-настройки: список URL, тип (HTML парсинг, RSS, API). Для конкурса достаточно 2–3 конкретных сайтов (например, Timepad, Stepik, Хабр События). | Высокий |
| 2.3 | Парсеры | Модуль `event_parsers/`: базовый класс или интерфейс, реализации под каждый источник (HTML + BeautifulSoup/selectors, RSS feed). Извлечение: заголовок, описание, ссылка, дата. | Высокий |
| 2.4 | Сопоставление с группами | По `group_topics` и ключевым словам из заголовка/описания определять, каким группам релевантно мероприятие. Учитывать синонимы (python = пайтон и т.д.). | Высокий |
| 2.5 | Планировщик парсинга | Задача в scheduler: раз в день (или по настройке) запускать парсинг, сохранять в `events`, дедупликация по url+date. | Высокий |
| 2.6 | Рассылка уведомлений | После парсинга: для каждого нового события определить группы → получить user_id по группам → отправить сообщение с заголовком, датой, ссылкой. Пометить событие как «разослано». | Высокий |
| 2.7 | Админка источников (опционально) | В table.py или отдельное окно: список источников, включено/выключено, последний парсинг. Для мая можно зашить 2–3 источника в конфиг. | Средний |

### 3.3. Пример маппинга групп на темы

- «Пайтон для начинающих», «Основы веб-программирования» → python, программирование, вебинар, разработка
- «3D моделирование», «Концепт-арт: Создание 3D-персонажа» → 3d, blender, концепт-арт, геймдев
- «Инженерная графика», «Архитектура и дизайн» → графика, cad, дизайн
- «Интеллект-школа. История», «Интеллект школа. Русский язык» → олимпиады, история, русский язык

### 3.4. Критерии готовности

- Не менее 2 рабочих источников мероприятий.
- Учащиеся получают в боте сообщения о релевантных мероприятиях без дублей.
- В документации описан принцип и пример конфига источников/групп.

## 4. Фаза 3: Развертывание под любую организацию

**Цель:** Организация (школа, центр доп. образования, компания) может «купить» проект и развернуть своего бота под себя: своё название, свои группы, свои источники событий, при необходимости свой бренд.

### 4.1. Требования

- Один экземпляр бота = одна организация (тенант).
- Настройки организации хранятся в конфиге/БД: название организации, список групп, при необходимости логотип/описание.
- Бот при старте и в приветствиях использует название организации.
- Админ-приложение может работать с разными БД (путь к БД в настройках) или генерировать конфиг под новое развертывание.
- Чёткая инструкция по развертыванию: установка, создание бота в Telegram, настройка .env, первый запуск, загрузка данных.

### 4.2. Технические задачи

| № | Задача | Описание | Приоритет |
|---|--------|----------|-----------|
| 3.1 | Конфиг организации | Файл `organization.yaml` или секция в .env: ORGANIZATION_NAME, ORGANIZATION_DESCRIPTION. Опционально: путь к логотипу, контакты поддержки. | Высокий |
| 3.2 | Группы из конфига | Список групп не хардкодить в коде, а читать из конфига (YAML/JSON) или из БД (таблица `organization_settings`). При первом запуске — создание конфига по шаблону. | Высокий |
| 3.3 | Тексты бота | Вынести строки приветствия, помощи, названия кнопок в языковой/конфиг файл (ru.yaml или messages.json), подстановка названия организации. | Высокий |
| 3.4 | Мульти-БД (опционально) | Для продвинутого сценария: выбор файла БД при запуске админки или переменная DB_PATH в .env. Один билд приложения — разные организации через разные .env и папки data. | Средний |
| 3.5 | Скрипт/инсталлятор развертывания | Скрипт (bash/powershell) или пошаговая инструкция: клонирование/распаковка, venv, pip install, копирование .env.example, запрос BOT_TOKEN и ORGANIZATION_NAME, первый запуск. | Высокий |
| 3.6 | Документация «Развертывание для организации» | Документ DEPLOYMENT.md: требования к серверу, создание бота в BotFather, настройка AI (Ollama/Groq), загрузка учащихся и расписания, настройка парсера мероприятий. | Высокий |

### 4.3. Критерии готовности

- Новая организация может развернуть бота за 30–60 минут по инструкции.
- В приветствии и помощи отображается название организации.
- Список групп настраивается без правки кода (конфиг или админка).

## 5. Дополнительный функционал для конкурса

Анализ похожих образовательных ботов и платформ (Duolingo, Учи.ру, боты вузов, чат-боты для курсов) показывает следующие направления, которые усиливают проект для жюри и пользователей.

### 5.1. Геймификация и вовлечение

| Идея | Описание | Сложность |
|------|----------|-----------|
| Достижения (badges) | За первое сообщение боту, за 10 вопросов к AI, за неделю подряд с просмотром расписания. Хранить в БД, команда /achievements. | Средняя |
| Простая статистика | Команда /stats: сколько вопросов задано, сколько занятий в расписании. Показывает личную «активность». | Низкая |
| Напоминания с мотивацией | Варианты текстов напоминаний в зависимости от дня недели или от группы. | Низкая |

### 5.2. Улучшение AI-репетитора

| Идея | Описание | Сложность |
|------|----------|-----------|
| Краткая история контекста | Хранить последние N сообщений пользователя в БД или в памяти и передавать в промпт (диалог в рамках сессии). | Средняя |
| Кнопки быстрых вопросов | Inline-кнопки: «Объясни тему», «Дай пример», «Проверь решение» — подставляют шаблон в запрос к AI. | Низкая |
| Оценка ответа | После ответа AI кнопки «Понятно» / «Не понятно» — логирование для аналитики (и при желании дообучение). | Низкая |

### 5.3. Администрирование и аналитика

| Идея | Описание | Сложность |
|------|----------|-----------|
| Простая аналитика в приложении | В table.py вкладка «Статистика»: количество учащихся по группам, количество записей расписания, последняя загрузка в БД. | Низкая |
| Логирование действий админа | Кто и когда загрузил данные (если появятся роли/логины — позже). Пока можно логировать «загрузка из Excel» и «загрузка в БД» с временем. | Низкая |
| Экспорт в Excel | Кнопка «Экспорт»: выгрузить текущие таблицы (учащиеся, расписание) в .xlsx для резервной копии или отчёта. | Средняя |

### 5.4. Надёжность и UX

| Идея | Описание | Сложность |
|------|----------|-----------|
| Обработка ошибок и повторные попытки | При недоступности Ollama — понятное сообщение и повтор запроса через N секунд (опционально). | Низкая |
| Резервный провайдер AI | В конфиге указать fallback (например, Ollama → Groq), при ошибке первого пробовать второй. | Средняя |
| Подтверждение перед массовой рассылкой | При загрузке новых данных в БД — опциональное напоминание «разослать уведомление о новом расписании?». | Низкая |

### 5.5. Безопасность и масштаб

| Идея | Описание | Сложность |
|------|----------|-----------|
| Ограничение доступа к боту | Режим «только зарегистрированные»: бот отвечает только user_id из таблицы учащихся. Остальным — сообщение «обратитесь к администратору». | Низкая |
| Rate limiting | Ограничение числа запросов к AI от одного user_id в минуту, чтобы избежать злоупотреблений. | Средняя |

Рекомендация для конкурса: в майский план включить 2–3 пункта с низкой сложностью (например, /stats, кнопки «Понятно/Не понятно», вкладка «Статистика» в админке, экспорт в Excel) и один с средней (достижения или история контекста для AI).

## 7. Критерии успеха и метрики

- **Фаза 1:** Администратор загружает один Excel с учащимися и расписанием и видит данные в приложении; загрузка в БД работает без ошибок.
- **Фаза 2:** Учащиеся минимум двух разных групп получают релевантные уведомления о мероприятиях; дубликаты не уходят.
- **Фаза 3:** По инструкции можно развернуть «новую организацию» (другое название, другой список групп) за время не более 1 часа.
- **Конкурс:** Презентация показывает полный цикл: загрузка из Excel → расписание и уведомления → мероприятия по группам → возможность развернуть бота под другую организацию; плюс 2–3 «фишки» из раздела 5.
- **Метрики (по желанию):** количество организаций, развернувших по инструкции; количество активных пользователей бота; отзывы тестовых администраторов.

## 8. Риски и митигация

| Риск | Митигация |
|------|-----------|
| Сайты мероприятий меняют вёрстку, парсеры ломаются | Использовать RSS где есть; для HTML заложить 2–3 источника; логировать ошибки парсинга и выводить в админку. |
| Не успеваем мультитенантность «в лоб» | Минимум: один конфиг организации (название + группы из файла), один бот на инстанс. Полноценную мультитенантность в одной БД оставить на пост-конкурс. |
| Жюри хочет видеть «продакшен» | Подготовить Docker-образ или чёткую инструкцию развертывания на VPS/облаке; демо-бот на тестовом токене. |
| Конфликт по срокам в команде | Закрепить ответственных по фазам; фаза 1 и 2 — критичны для демо, фаза 3 и доп. функционал — по остаточному принципу, но с фиксированным минимумом. |

## Краткое резюме для команды

1. **Фаза 1 (Excel):** Кнопка в table.py → выбор файла → парсинг → заполнение таблиц → при необходимости загрузка в БД. Общий модуль парсинга, маппинг колонок, валидация.
2. **Фаза 2 (Мероприятия):** Таблицы событий и маппинга групп, парсеры 2–3 сайтов, ежедневный парсинг, рассылка в боте по группам.
3. **Фаза 3 (Развертывание):** Конфиг организации (название, группы), тексты из конфига, DEPLOYMENT.md и скрипт/инструкция «под ключ».
4. **Доп. функционал:** Выбрать несколько пунктов из раздела 5 (статистика, достижения, экспорт, улучшения AI) и включить в бэклог до мая.
5. **Май:** Стабилизация, демо-сценарий, презентация и ответы на вопросы жюри.

Документ можно дополнять по ходу разработки (конкретные ссылки на задачи в трекере, уточнённые даты спринтов, решения по архитектуре).
